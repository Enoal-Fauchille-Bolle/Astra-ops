# Nginx Proxy Manager — 404 page, visitor addresses and origin pulls

`404.html` is the page a visitor sees when they reach an unknown subdomain of `enoal.fr`.
It follows the look of the portfolio at `enoal.fr` (same colours, same layout as its own
404), shows the requested address, and offers a link to `enoal.fr` plus a "Go back" button
when there is a previous page. It is a single self-contained file: fonts and icon are
embedded, nothing is fetched from another site.

## Where it lives

NPM keeps the page in its database, not in this repository. This file is the reference
copy.

1. **Settings → Default Site → Custom Page**: paste the whole content of `404.html` and
   save. NPM writes it to `/opt/docker-data/npm/data/nginx/default_www/index.html`, then
   switch the Default Site back to **404 Page** (see below). NPM only writes that file when
   Custom Page is saved and does not delete it when the setting changes.
2. **Proxy host 47 (`*.enoal.fr`) → Advanced**: reuses that file so that every unknown
   subdomain answers with a real 404 status and this page:

   ```nginx
   # Set error page to the file generated by NPM Settings
   error_page 404 /index.html;

   # Force 404 for all requests
   location / {
       return 404;
   }

   # Serve the custom HTML without redirect loops
   location = /index.html {
       root /data/nginx/default_www;
       internal;
   }
   ```

   `internal` stops `/index.html` from being opened directly, which would answer 200.

To check after a change: `curl -sk -o /dev/null -w '%{http_code}\n' --resolve
test.enoal.fr:443:192.168.1.201 https://test.enoal.fr/` must print `404`.

## Names outside `enoal.fr`

On port 80, a name that matches no host reaches NPM's Default Site: an unknown `.lan` name
(AdGuard sends every `*.lan` to Pulsar) or the bare IP. The Default Site is set to **404
Page**, so they get nginx's plain 404 page with a **404** status.

With Custom Page, they got the page above with a **200** status, because the template NPM
generates for a custom page (`try_files $uri /index.html`) sets no error code. Uptime Kuma
reads the status, not the page: a probe aimed at a mistyped `.lan` name stayed green.

A catch-all host for `*.lan`, like host 47, is not possible: the NPM form refuses a
wildcard that covers a whole top-level domain (`*.lan`, `*.com`).

To check: `curl -s -o /dev/null -w '%{http_code}\n' http://nosuchname.lan` must print
`404`, and a served name such as `http://portracker.lan` must still print `200`.

## Visitor addresses behind Cloudflare

`server_proxy.conf` is a copy of `/opt/docker-data/npm/data/nginx/custom/server_proxy.conf`,
which NPM includes in every proxy host. NPM reads the visitor's address from `X-Real-IP`, a
header Cloudflare does not send: the logs showed Cloudflare's addresses, and CrowdSec
analysed those. The file makes NPM read `CF-Connecting-IP` instead.

It also sets which connections may send that header. NPM rewrites `ip_ranges.conf` every
six hours with Cloudflare's ranges and CloudFront's, and anyone can put a CloudFront
distribution in front of the server. A list declared in a `server` block replaces the one
inherited from `http` instead of adding to it, so the header is only believed when the
connection comes from Cloudflare; a direct visitor keeps its own address, LAN included.
`IP_RANGES_FETCH_ENABLED: 'false'` does not help: it only skips the fetch at startup, the
six-hour timer still runs. Cloudflare publishes its ranges at
<https://www.cloudflare.com/ips/>; the file needs updating when they change.

Put it in `server_proxy.conf`, not `http_top.conf`: NPM's `nginx.conf` already sets
`real_ip_header` at `http` level, and a second one there makes nginx reject the whole
configuration (`"real_ip_header" directive is duplicate`), which takes every site down.
At `server` level it overrides the global value.

To apply a change without risk, `nginx -t` first: if it fails, nginx keeps running on the
old configuration.

```sh
docker exec nginx-proxy-manager sh -c 'nginx -t && nginx -s reload'
```

To check: `grep -h '\[Client ' /opt/docker-data/npm/data/logs/proxy-host-*_access.log | tail`
must show visitors' addresses, not Cloudflare's (`104.16.0.0/13`, `172.64.0.0/13`,
`141.101.64.0/18`…).

## Requests that skip Cloudflare

A name proxied by Cloudflare can also be reached by sending the request to the box's
public address, which would skip the WAF and the _CrowdSec bans_ rule. Authenticated
Origin Pulls (AOP, zone-level) refuses that path: Cloudflare presents a client certificate
signed by `aop-ca.pem` on every connection it opens to NPM, and an HTTPS request for a
protected name that arrives without it gets **403**.

- **Protected names**: `enoal.fr` and all its subdomains, except those in DNS-only mode
  (`immich`, `registry`, `rootssmp`), whose traffic never goes through Cloudflare. A new
  name is protected by default. **A new DNS-only name must be added to the
  `map $host $aop_protected` list** of `http_top.conf`, or it answers 403 to everyone
  outside the LAN and the VPN. The `.lan` hosts listen on port 80 only and are not
  concerned.
- **Exceptions**: connections from the LAN (`192.168.1.0/24`) and the VPN
  (`192.168.27.0/24`). The check reads `$realip_remote_addr`, the address of the
  connection itself, not `CF-Connecting-IP`, which any client can set.
- **`optional`, not `on`**: `ssl_verify_client on` refuses during the TLS handshake,
  before any rule runs, so the LAN and the VPN could not be let through (400). With
  `optional` the handshake succeeds and the `if ($aop_deny)` of `server_proxy.conf`
  decides.
- **`ssl_client_certificate`, not `ssl_trusted_certificate`**: it sends the name of the
  CA to clients, so a browser only offers certificates from that CA and shows no picker.
- **Side effect**: every HTTPS host asks for a client certificate, so nginx answers **421**
  when the `Host` header names another host than the one of the TLS handshake (SNI). That
  also stops reaching a protected name through the handshake of an unprotected one.

| File                | On Pulsar, in `/opt/docker-data/npm/data/nginx/custom/` | Role                                               |
| ------------------- | ------------------------------------------------------- | -------------------------------------------------- |
| `http_top.conf`     | `http_top.conf`, included at `http` level               | Asks for the certificate, computes `$aop_deny`     |
| `server_proxy.conf` | `server_proxy.conf`, included in every proxy host       | `if ($aop_deny) { return 403; }` after the real IP |
| `aop-ca.pem`        | `aop-ca.pem`                                            | CA certificate, public part only                   |

| Certificate                      | Where                                                                         | Expires    |
| -------------------------------- | ----------------------------------------------------------------------------- | ---------- |
| CA `CN=Astra AOP origin-pull CA` | `aop-ca.pem` in NPM; its key in Vaultwarden                                   | 2031-10-14 |
| Client certificate `CN=enoal.fr` | Cloudflare: SSL/TLS → Origin Server → Authenticated Origin Pulls → Zone-level | 2028-10-13 |

The CA key only signs new client certificates, it plays no part in a restore: lost with
Astra, a new CA does the same job. Cloudflare's _Zone-level Authenticated Origin Pulls
Certificate Expiration Alert_ (Notifications) sends an email 30 and 14 days before the
client certificate expires.

**To renew the client certificate**, sign a new one with the same CA and upload it in the
Zone-level part: Cloudflare uses the most recently deployed one. Delete the old one once
the new one is active. NPM needs no change while the CA stays the same. **To replace the
CA**, put the old and the new CA one after the other in `aop-ca.pem` and reload NPM, switch
the certificate in Cloudflare, then remove the old CA.

**To check**, from outside the LAN with the VPN off:
`curl -s -o /dev/null -w '%{http_code}\n' --resolve vault.enoal.fr:443:<box public IP> https://vault.enoal.fr/`
must print `403`; through Cloudflare, and from the LAN or the VPN, the same name answers
`200`.

**To undo**: remove the `if ($aop_deny)` block from `server_proxy.conf` and reload, which
stops the refusal at once. Then `http_top.conf` can go too, never before: the `if` would
name an unknown variable and `nginx -t` would fail.

## Fonts

Inter and JetBrains Mono (SIL Open Font License 1.1), taken from `@fontsource/inter` and
`@fontsource/jetbrains-mono` 5.3.0 (`*-latin-400-normal.woff2`, and `600` for the mono),
reduced with `pyftsubset` from `fonttools` to what the page can display, then embedded in
base64:

```sh
pyftsubset inter-latin-400-normal.woff2 --unicodes="U+0020-007E,U+00A0,U+2019" \
  --layout-features='kern' --flavor=woff2 --output-file=inter-ascii.woff2
pyftsubset jetbrains-mono-latin-400-normal.woff2 --unicodes="U+0020-007E,U+00A0,U+2019" \
  --layout-features='' --flavor=woff2 --output-file=jetbrains-mono-ascii.woff2
pyftsubset jetbrains-mono-latin-600-normal.woff2 --text="404" \
  --layout-features='' --flavor=woff2 --output-file=jetbrains-mono-600-digits.woff2
```

The kept range is printable ASCII: the requested address is always ASCII, since browsers
turn accented domain names into their `xn--` form. A new character in the text of the
page must fall in that range, or the fonts must be rebuilt.
