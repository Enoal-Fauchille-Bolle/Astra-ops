# Nginx Proxy Manager — 404 page

`404.html` is the page a visitor sees when they reach an address NPM does not serve: any
unknown subdomain of `enoal.fr`, or the server's IP on port 80. It follows the look of the
portfolio at `enoal.fr` (same colours, same layout as its own 404), shows the requested
address, and offers a link to `enoal.fr` plus a "Go back" button when there is a previous
page. It is a single self-contained file: fonts and icon are embedded, nothing is fetched
from another site.

## Where it lives

NPM keeps the page in its database, not in this repository. This file is the reference
copy.

1. **Settings → Default Site → Custom Page**: paste the whole content of `404.html`. NPM
   saves it and writes it to `/opt/docker-data/npm/data/nginx/default_www/index.html`.
2. **Proxy host 47 (`*.enoal.fr`) → Advanced**: reuses that file so that every unknown
   subdomain answers with a real 404 status and this page:

   ```nginx
   # Set error page to the file generated by NPM Settings
   error_page 404 /index.html;

   # Force 404 for all requests
   location / {
       return 404;
   }

   # Serve the custom HTML without redirect loops
   location = /index.html {
       root /data/nginx/default_www;
       internal;
   }
   ```

   `internal` stops `/index.html` from being opened directly, which would answer 200.

To check after a change: `curl -sk -o /dev/null -w '%{http_code}\n' --resolve
test.enoal.fr:443:192.168.1.201 https://test.enoal.fr/` must print `404`.

## Known gap

On port 80, a name that matches no host (the bare IP, for instance) reaches NPM's Default
Site, which serves the same page with a **200** status: the template NPM generates for a
custom page (`try_files $uri /index.html`) sets no error code. Subdomains of `enoal.fr`
are not affected, host 47 catches them first.

## Fonts

Inter and JetBrains Mono (SIL Open Font License 1.1), taken from `@fontsource/inter` and
`@fontsource/jetbrains-mono` 5.3.0 (`*-latin-400-normal.woff2`, and `600` for the mono),
reduced with `pyftsubset` from `fonttools` to what the page can display, then embedded in
base64:

```sh
pyftsubset inter-latin-400-normal.woff2 --unicodes="U+0020-007E,U+00A0,U+2019" \
  --layout-features='kern' --flavor=woff2 --output-file=inter-ascii.woff2
pyftsubset jetbrains-mono-latin-400-normal.woff2 --unicodes="U+0020-007E,U+00A0,U+2019" \
  --layout-features='' --flavor=woff2 --output-file=jetbrains-mono-ascii.woff2
pyftsubset jetbrains-mono-latin-600-normal.woff2 --text="404" \
  --layout-features='' --flavor=woff2 --output-file=jetbrains-mono-600-digits.woff2
```

The kept range is printable ASCII: the requested address is always ASCII, since browsers
turn accented domain names into their `xn--` form. A new character in the text of the
page must fall in that range, or the fonts must be rebuilt.
